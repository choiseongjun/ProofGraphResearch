# 워크플로 기반 AI 시스템 설계

ProofGraph는 단일 프롬프트나 비정형 에이전트 묶음이 아니라 **워크플로 런타임**으로 설계했습니다.

## 설계 계약

각 단계에는 책임, 명시적인 입력·출력 계약, 실패 정책, 관측 이벤트가 있습니다. 활성 워크플로인 `evidence-first-research`는 `GET /v1/workflows`에서 확인할 수 있고, 실행 시 이벤트 타임라인에도 버전과 함께 저장됩니다.

```text
주제 → 계획 수립 → 근거 수집 → RAG 검색 → 압축 → 관계 매핑 → 보고서 작성 → 비평·검토 → 지식 축적
```

| 시스템 관심사 | 설계 방식 |
|---|---|
| 오케스트레이션 | 조건부 수정 경로를 갖는 LangGraph 상태 머신 |
| 워크플로 계약 | 단계 정의, 버전, 품질 게이트를 가진 레지스트리 |
| 장기 실행 | FastAPI 요청 → Celery 큐 → PostgreSQL 영속 상태 |
| 컨텍스트 엔지니어링 | Writer 이전의 컨텍스트 압축 경계 |
| 지식 재사용 | 자동 웹 수집 → 청킹 → Ollama 임베딩 → pgvector RAG |
| 관계 추론 | Neo4j 근거 그래프 |
| 신뢰성 | 단계별 실패 정책, 재시도, 이벤트 타임라인, 원본 상태 DB |
| 사람 피드백 | Critic 수정 루프와 검수 데이터 기반 선택적 QLoRA |

## 면접 설명 문장

> “LLM 호출을 불투명한 챗봇이 아닌 경계가 있는 워크플로 단계로 설계했습니다. 각 단계는 데이터 계약, 관측 이벤트, 실패 정책, 영속 상태 전이를 가지며, 실행 과정에서 검증된 근거는 RAG와 그래프 데이터베이스에 축적돼 이후 워크플로에 재사용됩니다.”
