# 3분 데모 스크립트

## 0:00 — 문제와 시스템 소개

“ProofGraph는 단순 챗봇이 아니라, 근거 수집부터 RAG 지식 축적까지를 워크플로로 관리하는 AI 시스템입니다.”

`http://localhost:3000`의 **워크플로 계약**에서 `계획 수립 → 근거 수집 → RAG 검색 → 압축 → 관계 매핑 → 보고서 작성 → 비평·검토 → 지식 축적` 단계를 보여줍니다.

## 0:30 — 자동 근거 수집과 RAG

**RAG 자동 수집·색인**에 “2026년 한국 AI 에이전트 시장 전망”을 입력합니다. URL을 직접 넣지 않아도 검색 쿼리 분화, 공개 웹/PDF 수집, 청킹, Ollama 임베딩, pgvector 저장이 이어진다고 설명합니다.

## 1:10 — 워크플로 실행

**리서치 워크플로 실행**에서 동일한 주제를 실행합니다.

- FastAPI는 즉시 작업 ID를 반환합니다.
- Celery Worker가 장기 리서치를 수행합니다.
- PostgreSQL이 상태·이벤트·출처의 원본 저장소입니다.
- Retriever가 이전에 축적한 RAG 근거를 함께 사용합니다.

## 1:50 — 결과 검증

완료된 보고서 아래에서 다음 버튼을 순서대로 보여줍니다.

1. **출처 확인**: 보고서 근거와 원문 URL 검토
2. **품질 점수 확인**: 인용 유효성·출처 범위 확인
3. **근거 그래프 확인**: Neo4j에 저장된 출처·엔티티 관계 확인
4. **Markdown/PDF 내보내기**: 검증된 결과의 활용

## 2:30 — 설계 판단 강조

“Redis는 작업 상태를 보관하지 않고 Celery broker로만 사용했습니다. 작업 상태와 감사 가능한 실행 이력은 PostgreSQL에 저장했습니다. Neo4j는 관계 탐색, pgvector는 의미 기반 근거 재사용이라는 서로 다른 목적을 담당합니다.”

## 2:50 — 확장 방향

“검수된 보고서 데이터가 쌓이면 QLoRA 파이프라인으로 Writer 품질을 개선할 수 있습니다. 다만 현재는 학습 결과를 과장하지 않고, 검수 데이터와 GPU 평가가 선행돼야 한다는 기준을 유지했습니다.”
